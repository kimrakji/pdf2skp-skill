# 도입 평가

첫 평가는 첨부 도면 3개의 원본·추출 이미지·선택 이미지·실제 SketchUp 모델을 디자이너와 대조한다. 현재 추출 성공은 자동 벽체 인식 성공이 아니다.

1. 정답 평면도 영역, 실제 치수 두 쌍, 벽체와 가구 구분, 낮은 벽체, 미지원 개구부를 확정한다.
2. 같은 결정 JSON을 3번 실행해 geometry hash와 벽체 개수·XY 좌표·높이가 같은지 확인한다.
3. 서로 다른 디자이너가 같은 Skill에 파일과 같은 높이만 주고 각각 3회 실행한다. AI 선택의 벽체 누락, 가구 오인, 축척 오차를 정답과 비교한다. 이 실험 전에는 사람 간 일관성 개선을 입증했다고 말하지 않는다.
4. 높이를 2700→3200 mm로 바꿀 때 기본 벽체의 XY 윤곽과 그룹은 같고 높이와 부피만 달라져야 한다. 낮은 벽체는 공통 정책값을 유지한다.
5. native exporter의 저장 전·C API 재열기 검사를 확인한다. 별도 프로세스의 `verify-native`로도 치수, Z 높이, 솔리드, 구멍, 그룹·태그·원본 속성을 검사한다. C API 보고서의 `reopen_verified`는 native 파일 읽기 성공이며 Desktop 화면·편집 확인은 `desktop_reopen_verified`로 구분한다. 최종 도입 평가에서는 SketchUp에서 파일을 직접 열어 화면과 편집을 확인한다. 기존 Ruby 보고서의 `reopen_verified: false`는 Desktop 재열기 미수행을 뜻한다.
6. 회사 담당자가 허용 오차와 실패 시 추가 입력 범위를 정한 뒤 회사 규칙을 확정한다. 현재 confidence 0.9, 축척 오차 2%, 기본 높이 2700 mm, 낮은 벽체 1200 mm는 평가용 가정이다.

밑그림 모드에서는 닫힌 선 윤곽과 수평·수직 평행 선의 겹침 구간을 추정 벽체로 출력한다. 스캔, 미지원 곡선, 자가 교차, 문창 상세, DWG는 원본 참조 또는 후속 범위로 남는다. 부분 복원과 원본 참조 출력을 완성 도면으로 평가하지 않는다. 평가는 추가 질문 없이 초안을 출력하고 사용자가 수정하는 양을 줄이는지를 중심으로 한다.
